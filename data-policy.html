Data & Sources

Important: “Live” does not mean instantaneous. “Authoritative” means the provider is a recognised source for that domain, not that every observation is infallible. Climate, air-quality, freshwater and development layers can be annual or historical; orbital positions are propagated from time-stamped elements.

3D Earth is a presentation layer. The following services and datasets provide the underlying map, weather, location and live-feed information shown in the application.

2. Location data

When location is enabled, the browser supplies WGS84 latitude and longitude together with an accuracy estimate. The application uses these coordinates to position the globe, map and location-aware requests. Manual coordinate entry provides an alternative when browser positioning is unavailable or not desired.

3. Weather data

Weather requests are routed through the application's weather endpoint. The current implementation uses Open-Meteo with automatic timezone resolution and model selection. Open-Meteo's free API is restricted to non-commercial use; production or commercial use should be moved to a licensed endpoint or another provider before launch.

4. Live and derived layers

Some visual layers are calculated locally from astronomical or orbital formulas rather than fetched as a single authoritative dataset. Other layers depend on external feeds. A rendered point, orbit or overlay should therefore be interpreted as a visualization of the available inputs, not as a guarantee of real-world position at a specific instant.

6. Operational notes

Provider policies can change independently of this application. In particular, OpenStreetMap's standard tile service is intended for normal interactive viewing and requires visible attribution, appropriate identification and caching; it is not a general-purpose commercial tile backend.

For sustained commercial traffic, use a suitable licensed map and weather provider or operate infrastructure appropriate to the expected volume.
